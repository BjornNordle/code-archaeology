What is code-archaeology?

A per-commit architecture scanner. You register a git repo here, the scanner walks its history (every commit, or a filtered subset), runs a Python AST analyzer on each commit, and stores per-module metrics in SQLite.

Once data is in, the repo page shows how the codebase's size, coupling, and cohesion evolved over time, and a per-commit snapshot page shows the full architecture (module graph, coupling matrix, layered view, ORM diagram) at any point in history.

Limitations to know up front
  • Python-only AST. Classes, methods, fan-in/out, and LCOM4 are only computed for .py files. Other languages get a per-extension LOC count as a fallback.
  • Linear history. The walk is git log --first-parent --reverse. Merge commits are followed via their first parent only — good enough for main-style histories.
