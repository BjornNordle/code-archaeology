Force-directed module graph. Node size = LOC, color = package. Click to highlight.
How to read this graph

Every Python module is a node; every internal import is an arrow from importer to imported. External libraries (stdlib, third-party) aren't shown.

Visual encoding
  • Node size — 6 + sqrt(LOC)/2, so a 10× larger module is ~3× bigger visually rather than 10× (avoids one giant blob dominating the layout).
  • Node color — app root, routers (anything with routers. in its dotted name), data layer (modules ending in database, scanner, or analyzer).
  • Arrow thickness — sqrt(weight), where weight = total distinct names imported between the two modules.
Interactions
  • Click a node to highlight its incoming/outgoing edges and see the name lists below.
  • Drag a node to pin it; the simulation continues around it.
  • Wheel to zoom, drag empty space to pan (useful when there are 20+ modules).

Labels strip the longest shared dotted prefix client-side: if every module starts with app., that prefix is hidden so the names stay readable.

Coupling & cohesion metrics

Ca afferent · Ce efferent · I = Ce/(Ce+Ca) · LCOM4 = method-cluster count (lower = more cohesive).
What is instability (I)?

A 0–1 ratio measuring how exposed-to-change a module is, from Robert C. Martin's stability metrics.

I = Ce / (Ce + Ca)

Ce (efferent coupling) = how many internal modules this one imports. Ca (afferent coupling) = how many internal modules import it. If both are zero, I defaults to 0.

  • I = 0 — stable: many depend on it, it depends on none. Hard to change without breaking the world.
  • I ≈ 0.5 — mid: balanced.
  • I = 1 — unstable: depends on many, nothing depends on it. Cheap to change.

Healthy codebases mix cores near 0 with leaves near 1. A module high in both Ca and Ce is a fragile bottleneck — refactor candidate.

What is cohesion (LCOM4)?

LCOM4 — Lack of Cohesion of Methods, version 4 — asks: is this class actually one thing, or several things bolted together?

How it's computed, per class

Treat each method as a node. Connect two methods if they reference the same instance attribute (e.g. both touch self.config). LCOM4 = the number of connected components.

  • LCOM4 = 1 — one cluster, everything is related. Coherent.
  • LCOM4 = N > 1 — N islands sharing no state. The class is really N classes glued together.
  • LCOM4 = 0 — no methods.

The column shows the average over the module's top-level classes. — means the module has no classes.

Caveat: only attribute references via self.X create edges; inheritance and method-to-method calls (unless the called name is also referenced elsewhere as an attribute) aren't tracked.

Coupling matrix

Rows import columns. Cell intensity = number of imported names. Diagonals are self-references (always blank).
How to read this matrix

An N×N grid answering, per cell: how many distinct names does the row module import from the column module? Brighter cells = more names imported.

  • Rows import columns. A bright cell at row main × column database means main.py does something like from database import a, b, c.
  • Diagonal is always blank — self-imports aren't tracked.
  • Hover a non-blank cell for the exact name count.
Patterns to look for
  • Dense rows = high Ce (the module knows about lots of others — leaf-like).
  • Dense columns = high Ca (lots of modules depend on it — a stable core).
  • Clusters of bright cells grouped together reveal sub-systems that depend mostly on each other.

Architectural layers

What does this diagram show?

A Mermaid flow diagram that groups modules into roles and shows imports between layers (not between individual modules — for that, use the force graph at the top of the page).

How layers are detected
  • main — module whose dotted leaf-name is main.
  • routers — anything matching routers.* in its name.
  • data — module whose leaf-name is database.
  • services — everything else that main / routers depend on.

If no module fits a layer at this commit, that subgraph is dropped from the diagram.

Why it matters

Helps spot architectural drift. Arrows should generally point inward (routers → services → data), not outward — a data-layer module reaching back into routers is a smell.

What does this diagram show?
