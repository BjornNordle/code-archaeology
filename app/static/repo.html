How to read these charts

Each chart plots one aggregate metric across every scanned commit, oldest (left) to newest (right). X-axis labels are the short SHA of each commit.

  • LOC — total raw line count across all Python modules. A size proxy; sudden jumps usually mark a refactor, a vendored dependency, or a generated-file commit.
  • classes — total top-level classes across all modules at each commit.
  • avg instability — mean of the per-module instability ratio (0–1). See the Instability panel below.
  • avg LCOM4 — mean of per-module cohesion across modules that have classes. Modules without classes are skipped. Gaps render where no commit had any classes. See the Cohesion (LCOM4) panel.

Click any point to jump the scrubber to that commit, then use the Open architecture snapshot link to see the full module graph and per-module metrics at that revision.

What is instability?

A 0–1 ratio measuring how exposed-to-change a module is, from Robert C. Martin's stability metrics (1995).

I = Ce / (Ce + Ca)

Where Ce (efferent coupling) is how many internal modules this one imports, and Ca (afferent coupling) is how many internal modules import it. If both are zero, I defaults to 0.

How to read it
  • I = 0 — maximally stable: many modules depend on this one, it depends on none. Hard to change without breaking the world. Typical of domain models and framework cores.
  • I ≈ 0.5 — mid: balanced incoming and outgoing dependencies.
  • I = 1 — maximally unstable: depends on many, nothing depends on it. Cheap to change. Typical of UI glue, entry points, scripts.
What's healthy

The Stable Dependencies Principle says depend in the direction of stability: stable modules shouldn't import unstable ones. A healthy codebase usually shows a mix — cores near 0, leaves near 1. The worrying case is a module with high Ca and high Ce: everyone depends on it and it depends on lots, making it a fragile bottleneck.

What is cohesion (LCOM4)?

LCOM4 — Lack of Cohesion of Methods, version 4 — asks: is this class actually one thing, or several things bolted together?

How it's computed, per class

Treat each method as a node. Connect two methods with an edge if they reference the same instance attribute (e.g. both touch self.config). LCOM4 is the count of connected components in the resulting graph.

  • LCOM4 = 1 — one cluster: every method shares some state with another. The class is one coherent thing.
  • LCOM4 = N > 1 — N islands of methods that share no state. The class is really N classes glued together — a candidate for splitting.
  • LCOM4 = 0 — the class has no methods. Cohesion isn't meaningful, so it's reported as 0 and the module average excludes it implicitly via the "no classes → —" rule.

At the module level (what the chart and table show), it's the arithmetic mean over the module's top-level classes. — means the module has no classes.

Caveats with this implementation
  • Connections come from shared self.X attribute references. A method-to-method call like self.bar() adds bar to the caller's reference set, so it only connects to bar if some other method also references the name bar.
  • Only top-level classes are analyzed — nested classes are ignored.
  • Inherited attributes aren't tracked — only what's referenced directly via self in the class body.

Hotspots — modules with worst-trending metrics

What are hotspots?

Modules whose metrics moved the most across a window of recent commits. The window's oldest commit is compared to its newest (HEAD) — so window=20 compares HEAD against the commit 19 ahead of it.

Columns
  • LOC now / I now / LCOM4 now — the metric's current value at the latest commit.
  • ΔLOC / ΔI / ΔLCOM4 — change across the window. +positive = grew (more code / more unstable / less cohesive). −negative = shrank. 0 = unchanged.
  • new — module didn't exist at the window's start. Deltas are computed against zero, which is why a brand-new module's ΔLOC equals its current LOC.
Sort order

Rows are sorted by (ΔLOC, ΔI) descending — modules that grew most in lines and stability appear first. The top 30 are shown.

Why it matters

Hotspots concentrate risk. A module that's growing in LOC and losing cohesion and becoming more unstable is technical debt accumulating in real time — usually worth a refactor before it gets worse.
